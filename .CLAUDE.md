# EraBots

- v2.0

   - Doctrine Quantum‑Era / Militaire‑Tech

> Fichier doctrinal permanent pour tous les agents IA opérant dans le dépôt EraBots v2.0.  
> Ce document définit les règles, permissions, limites, conventions et objectifs du framework.  
> Il sert de mémoire persistante, de protocole d’engagement et de garde‑fou technique.

---

🟦 1. Mission du projet

EraBots v2.0 est un framework multi‑bots modulaire, conçu pour orchestrer :  
- des agents IA (OpenAI Agents, Claude, Copilot, bots internes)  
- un EventBus centralisé  
- un SessionManager persistant  
- un moteur d’orchestration intelligent (Engine v2.0)  
- des modules indépendants, extensibles, sécurisés  

Objectif : stabilité, modularité, sécurité, évolutivité vers EraBots v3.0 (Mesh Distributed Bots).

---

🟩 2. Architecture officielle (v2.0)

```text
EraBots/
│
├── core/
│   ├── engine.py
│   ├── eventbus.py
│   └── session.py
│
├── agents/
│   ├── agents_engine.py
│   ├── text_agent.py
│   ├── voice_agent.py
│   └── sandbox_agent.py
│
├── modules/
│   ├── echo_bot.py
│   ├── analysis_bot.py
│   ├── openai_agent.py
│   └── sandbox_agent.py
│
├── assets/
│
├── main.py
├── config.yaml
├── requirements.txt
└── README.md
```

Règles IA :
- Ne jamais renommer les dossiers core/, agents/, modules/  
- Ne jamais fusionner core/ et agents/  
- Ne jamais supprimer un module existant sans ordre humain  
- Respect strict de la séparation Engine / EventBus / SessionManager

---

🟥 3. Zones interdites pour les agents IA

Les IA NE DOIVENT PAS :

- modifier core/engine.py sans ordre explicite  
- toucher aux mécanismes internes du EventBus  
- réécrire SessionManager  
- supprimer ou fusionner des modules  
- changer la structure du projet  
- inventer des dépendances dans requirements.txt  
- créer des fichiers hors architecture officielle  
- modifier la sécurité ou les permissions sans ordre humain  
- exécuter du code système ou des commandes dangereuses  

---

🟧 4. Zones autorisées

Les IA PEUVENT :

- créer de nouveaux bots dans modules/  
- créer de nouveaux agents dans agents/  
- améliorer la documentation  
- optimiser du code existant sans changer l’architecture  
- ajouter des tests unitaires  
- proposer des refactorings non destructifs  
- améliorer la lisibilité, modularité, robustesse  

---

🟨 5. Style de code obligatoire (Doctrine EraBots v2.0)

Python :
- PEP8 strict  
- classes courtes, modules indépendants  
- fonctions ≤ 40 lignes  
- pas de logique cachée  
- pas de magie implicite  
- logs structurés  
- exceptions explicites  
- commentaires doctrinaux :

`

[ERA] Raison de la décision

[SEC] Sécurité / Permission

[FLOW] Flux d’événements
`

🟫 7. Conventions pour les nouveaux bots

Chaque bot doit :

- être dans modules/  
- avoir un nom clair : xxx_bot.py  
- contenir une classe XxxBot  
- implémenter :  
  - handle(message, session)  
  - metadata()  
- être compatible EventBus v2.0  
- être compatible SessionManager v2.0  

---

🟦 8. Conventions pour les agents OpenAI

Les agents doivent :

- être dans agents/  
- utiliser AgentsEngineV2  
- déclarer leurs outils explicitement  
- ne jamais exécuter de code système  
- ne jamais inventer des API OpenAI  
- respecter les sessions persistantes  
- suivre les règles BlueSecurity
